# Agent loop

Code-agent 已将 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的执行内核**以原始 TypeScript 源码合并进仓库**，基线为 `dsh-v0.2.1-rc.1`，提交 `1600d8a1e140dcde43a1a0941940a0480712c011`。循环、会话、模型协议、工具调度与所需基础服务均从本地源码构建，不再在运行时加载 npm 上的 `@deepseek-ai/dsh-*` 包。

源码位于 `code_agent/harness/node/vendor/deepseek-harness/`，本项目的构建入口为 `code_agent/harness/node/src/index.ts`，产物为 `core.mjs`。上游来源记录见同目录的 `UPSTREAM.json`，许可证见 `THIRD_PARTY_NOTICES.md` 与合并源码中的 `LICENSE`。这些文件均随 npm 包和 Python wheel 分发，维护者可以直接修改本仓库内的实现并重建。

内核仍由本地 Node 子进程运行，Python 通过标准输入输出中的 JSONL 消息提供模型、工具与产品事件。运行需要 **Node.js 22.14+**、**Python 3.11+**，无需 DeepSeek Harness Desktop。源码构建时使用锁定的 esbuild 与 Zod；运行时产物已包含必要实现，不需要 npm、node_modules 或网络下载 Harness 依赖。真实模型调用及联网工具仍依照配置访问网络。

## 执行流程

1. Python 接收用户输入，装配会话、附件、项目上下文与当前可用工具。
2. 本地合并的 Harness 内核请求模型，由 Python 模型适配器完成调用并转发流式输出。
3. 模型提出工具调用后，Harness 调度工具；Python 逐次执行权限检查、必要审批、文件写入租约和现有工具实现。
4. 工具结果返回 Harness，内核决定继续请求模型还是结束本轮。
5. 产品层保存会话事件、用量与执行结果；取消、后台任务和多智能体生命周期继续由会话运行时接入。

旧循环中的任务类型猜测、动态摘除工具、连续读取后强制收口、额外验收追问等启发式策略不再驱动执行。工具可用范围、授权与实际验证结果继续由产品层约束；合并源码不会扩大用户已有权限。

## 当前源码与重复读取

Python 适配层保留已成功读取、版本仍有效的源码回执，避免每次发给模型前将当前文件一律缩成 2000 字符。原生编辑回执中的新源码视图也可复用。源码仍计入总上下文预算；超大内容会明确标记省略，不宣称模型已掌握被丢弃的部分。历史回执保持工具数据，不提升为系统指令。

同一版本的完整读取与已覆盖窗口按实际行范围去重，稳定的单文件搜索结果也可保留。仅当覆盖它的完整回执确实留在本次模型请求中，重复正文才折叠为引用；不相交窗口分别保留。大回执放不进预算时，较小窗口仍有机会保留，避免因去重失去唯一可用的源码。

并行读取超出预算时，空正文不占用源码份额，较小的结果优先完整保留，其余内容明确标记截断。重复正文释放的空间用于保留其他源码，并重新确认覆盖回执仍然完整可见。用户约束、调用与结果配对和模型私有协议完整计入预算。

默认基础历史预算为 24,000 字符。当模型容量已知、且已验证的当前源码工作集需要更多空间时，可按需增长到最多 48,000 字符；系统、工具定义、模型输入硬上限及输出预留始终约束实际额度。显式设置 `CODE_AGENT_HISTORY_BUDGET` 会固定上限，未知容量不启用扩容。重复读取与重叠窗口不推动预算增长。界面上下文用量使用本次实际选定的预算；`.env.example` 中的固定上限默认注释，避免安装时无意禁用自适应行为。

旧安装若保留了早期模板中的 `CODE_AGENT_HISTORY_BUDGET=24000`，可注释该行启用自适应；需要固定预算时继续显式设置。本次已将本机旧模板默认值注释，其他本机配置保持原值。

新源码进入后，较旧的当前源码组也可使用剩余预算部分保留，避免因无法容纳整个并行组而把其中仍可完整保留的文件一并丢弃。较小的最新执行结果优先保留，防止测试输出被旧源码挤掉。截断回执不会成为完整覆盖的证明。

跨文件证据仍因历史协议开销被挤出时，适配层使用已验证版本的原始回执生成独立、不可信的数据快照。快照正文、用户约束、近期工具调用及私有协议共用实际选定的预算；较小文件可完整保留，较大内容明确标注摘录。原调用与结果保持配对，快照不合成新的工具执行、不读取未授权内容，也不代表验证通过。完整回执、完整源码范围覆盖与摘录分别记录；完整视图未实际保留时，不能用它消除包含中间代码的真实窗口。

快照按路径成本分组；同版本标准编号窗口按实际行号合并，保留来源、搜索匹配统计和裁剪说明，未知格式或冲突内容保持原样。完整文件更省时优先保留完整文件，避免被更昂贵的重叠窗口替代。此前被截断的回执恢复完整可见时，会补记为已观察证据，后续重复读取可正常触发提醒。

快照每次请求重新校验和生成。缓存最多保留 24 份回执，满额时优先移除同版本已覆盖的重复视图，避免几十次重复窗口把其他文件的唯一完整证据挤掉；快照最多涉及 6 个路径。

代码助手与 Lead 的执行规程要求实现和必要新增测试作为同一批次完成，再运行完整验收。新增用例沿用现有真实接口与夹具，关注本次变化，避免重复生成已有套件覆盖的组合；验证失败先定点修复，用户要求的完整验收范围不变。

源码保留按真实路径、文件版本和可用摘要校验。文件改动、删除或路径指向变化后，旧回执不再作为当前源码；小文件的摘要检查也能发现同大小、同修改时间的内容变化。自动检查点续跑沿用证据，新用户任务重置本轮保留状态。保留上下文不代替实际读取授权，也不绕过编辑前的文件新鲜度检查。

重复读取提醒按模型实际可见的行覆盖和检索证据计数，涵盖原生读取与可识别的只读 Shell 读取交替。未知 Shell、等待和失败不会假装产生进展，也不会清空已有计数。提醒只在指定阶段出现，不缩减可用工具、不拦截必要重读、不强制回答或提前结束任务。

## 流式请求恢复

AgentLoop 按请求启用支持预览重置的流式恢复。收到完整终结响应前发生连接中断时，按现有重试次数上限丢弃本次未完成的正文、思考和工具片段，清理当前预览，再用相同输入重新生成。工具仅在完整模型响应提交后调度；重试不重新执行已完成的工具。

取消、鉴权失败不触发恢复；终结响应已收到后，尾部连接中断不重新生成。缺少 `finish_reason` 和 `[DONE]` 的 EOF 视为不完整响应，不能提交工具。不支持预览重置的其他 Provider 调用者维持原来的增量后失败行为，避免重复拼接正文。重置事件只带重试元数据，不保存失败生成中的思考或工具参数。

## 本地构建与准备

```bash
pip install -e ".[dev]"
npm ci --ignore-scripts --no-audit --no-fund
npm run build:harness
npm run check:harness
python -m code_agent.harness --prepare
```

`build:harness` 从仓库内源码生成 `core.mjs` 与 `core-build.json`，后者记录输入文件和产物的内容摘要。`check:harness` 无需构建依赖即可检查源码与产物是否一致。修改源码后重新运行构建；缺少产物或产物过期会明确报错，不会悄悄切回 npm 下载的实现。

准备命令只检查 Node 与包内内核，不发送模型请求，也不安装 npm 依赖。npm 启动器自动执行这个检查；单独安装 Python wheel 同样直接使用包内构建产物。程序升级与重新构建不会覆盖用户工程、会话或密钥。

`CODE_AGENT_NODE` 可指定 Node 可执行文件。`CODE_AGENT_HARNESS_NODE_DIR` 可由部署方指定完整内核资产的绝对目录，包括源码、`runner.mjs`、`core.mjs`、来源与构建清单；npm 启动器自动指向发行包的对应目录。
