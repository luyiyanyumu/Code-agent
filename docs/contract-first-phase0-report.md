# 阶段 0 实验报告（契约骨架编程）

> 实验清单：`docs/contract-first-phase0-checklist.md`　设计文档：`docs/contract-first-design.md`
> 实验环境：`E:\csp-phase0\`（**主仓库未被触碰**；只用现有能力，未写任何产品代码）

## 0. 结论（先看这三句）

1. **"实现可丢弃"在证据覆盖范围内成立**：4 个独立实现（实验 B 一个、实验 A 三个），
   全部**一次通过**全部测试、契约层（签名/数据/import）**一字未改**、证据文件未被动过。
2. **契约不够——但不够的方式和预期不同**：10 条被判定的义务里有 **8 条**被实现者标为
   "有歧义 / 只能靠猜"，另有 **2 条被指出字面不可能同时满足**。
3. **真正的危险不是"两个实现不一致"，而是"三个实现一致地猜错"**：
   13 个未定义边界上三个实现行为**完全一致**（同一模型族群猜测高度趋同），
   唯一出现分歧的 2 个探测点，恰好落在契约里**两句话字面冲突**的地方——
   也就是说，**只有契约自己写错或写漏的地方才会被抓到，猜错的地方一个都抓不到。**

## 1. 实验 B：已有模块按契约重生成（`agent/routing.py`）

| 项 | 值 |
|---|---|
| 冻结输入 | 127 行原实现 + 127 行契约（10 条义务、5 条路由数据、4 条拓扑边） |
| 骨架 | 127 行（签名 + 义务注释 + `NotImplementedError`；数据段原样保留） |
| 证据 | 3 个纯单测（12 断言）+ 2 个集成测试（system prompt 真的带上提示） |
| 实现者 | 1 个全新上下文子代理（看不到原实现） |
| **填体结果** | **3/3 纯测试 + 5/5 全套测试一次通过，0 返工** |
| 形状闸门 | PASS（7 个公开符号 + 4 个 import 与原骨架逐字一致） |
| 证据文件 | SHA256 未变（`6069C397B973215B`） |
| **行为差分** | 37 个案例：一致 21，**文案不同 16，语义不同 0** |

**差分明细**（`behave_diff.py` + `diff_class.py`）：

- `classify`：**12/12 完全一致**
- `route_hint`：25 案例 → 9 一致、**16 仅"文案格式"不同**（工具集合与顺序两边完全相同）、**0 语义不同**
- 差异长这样：
  - 原实现：`[工具路由｜改代码] 这类任务通常只需要：code_map、grep、file…。先定位再改…`
  - 重生成：`[工具路由｜改代码] 推荐工具：code_map, grep, read_file…。先定位再改…`
- **测试抓不到它**：那 5 个测试只断言"前缀 + 哪些名字不出现"，没有任何一条断言文案本身。
  于是"5/5 全绿"完全无法反映这次行为变更。
  → **这就是本次实验最重要的一条**：**证据的边界就是契约的边界**。契约没写输出格式，
  证据没断言输出格式，AI 就会自由发明一个，而且所有闸门都会放行。

**实现者自己交出的"只能靠猜"清单（5 条，未删改）**：

1. OBL5×OBL4 的**先后次序**未定义（先过滤再截断，还是先截断再过滤）——今天不可观察（所有路由 ≤6 个工具），
   一旦某路由超过 6 个工具才会显现；
2. **OBL8 只由"数据"保证，不由"代码"保证**（它靠人眼核对 hint 文本里不含工具名，
   将来有人往 hint 里嵌工具名会静默破掉，且无测试报警）；
3. **输出行的具体格式是它发明的**（`推荐工具：` 这个措辞、半角逗号、中文句号收尾，契约里都没有）；
4. "类空输入"的边界（`"   "`、`route` 不是 Route 时的兜底）；
5. "写进 system prompt 末尾"由调用点负责拼接——契约没显式断言。

## 2. 实验 A：新模块（`sessions/stats.py`，会话事件流统计）

| 项 | 值 |
|---|---|
| 冻结输入 | `_skeleton.py`（32 行）+ 契约（12 条义务，其中 2 条性能义务标为不判定） |
| 证据 | 9 个测试（约 40 断言，**先于实现写**，逐条挂到 OBL 上） |
| 实现者 | 3 个全新上下文子代理（r1 / r2 / r3） |
| **9/9 证据** | **r1 ✅ r2 ✅ r3 ✅ 全部一次通过** |
| 形状闸门 | r1/r2/r3 全部 PASS（2 个公开符号 + 4 个 import 与骨架一致） |
| 证据文件 | 三份 SHA256 均为 `8F0649D5E9FB044B`（未被动过） |
| 实现规模 | 96 / 110 / 117 行（风格各异：dict 累积 vs 显式变量、helper 数量不同） |
| **分歧探测** | 16 个边界探测点 → **14 一致，2 分歧**（见 §3） |

**三份报告合起来标出的"有歧义 / 靠猜"义务（唯一义务数）**：

| 义务 | 歧义词 | 被几份报告标出 |
|---|---|---|
| OBL2 / OBL5 | **"不为真"** —— Python 真值性 还是 `is True`？（`auto="false"` 会翻转结论） | 3 |
| OBL8 | **"整数"** —— `True` 算不算？`2.0` / `"3"` 算不算？负数 clamp 吗？ | 3 |
| OBL8 | **"不是 dict"** —— 字面义，还是"取不到字段"的简写？ | 2 |
| OBL9 | **"若是枚举" / "归一成字符串"** —— 解包深度？非 str 的 `.value`？大小写？ | 3 |
| OBL6 | **"总数"** —— 垃圾输入、源中途抛异常，算不算？ | 3 |
| OBL10 | **"同一个输入"** —— 一次性生成器字面不可能"两次结果相同"（与 OBL1 冲突） | 3 |
| OBL1 | "空输入"是否包含**不可迭代**输入（`None` / `42`） | 2 |
| OBL7 | **"usage 的字段"** —— usage 是非 dict 对象时，OBL7 与 OBL8 字面互斥 | 1 |

→ **10 条被判定的义务里 8 条有歧义（80%）**，其中 4 条被三份报告同时标出。

**被指出的"字面不可能同时满足"（2 条）**：

- **OBL1 × OBL10**：OBL1 要"已耗尽的迭代器返回全零"，OBL10 要"同一输入两次结果相同"——
  对生成器，第一次非零、第二次全零，**任何实现都无法同时满足**。唯一自洽解读是把"同一输入"
  限制为可重复迭代容器（证据里正是传 list），而契约没写这个限定。
- **§4「任何情况下不得抛异常」**：`except Exception` 抓不到 `KeyboardInterrupt` / `SystemExit`；
  要字面满足就得 `except BaseException`（吞掉 Ctrl-C）。"任何情况"把义务写到了不可满足的强度。

## 3. 分歧探测：把"靠猜"变成可观察的分歧

探测器 `stats_diff.py`（16 个探测点，每点比较 8 个字段）+ 两个灵敏度对照：

| 对照 | 结果 | 说明 |
|---|---|---|
| 骨架 vs r1 | **16/16 判为分歧** | 探测器不是橡皮图章 |
| 只差 `errors+1` 的变异体 vs r1 | **16/16 判为分歧**，并逐字段打印出差异 | 单字段 1 单位的差异也抓得到 |
| **r1 vs r2 vs r3** | **14 一致，2 分歧** | 见下 |

**2 个分歧点，正好落在 OBL7 与 OBL8 的字面冲突上**：

```
[DIFF] usage 是非 dict 对象（OBL7 与 OBL8 字面冲突点）
    r1: (…, input=3, output=1)      # 读对象属性 → 按 OBL7 累加
    r2: (…, input=3, output=1)      # 读对象属性
    r3: (…, input=0, output=0)      # 按 OBL8 字面：不是 dict → 按 0 计
```

r3 在实现之前就**用文字预告了这个冲突**（"OBL7 说对每个 done 累加 usage 的三个字段，
OBL8 说 usage 不是 dict 按 0；两句互斥；我按 OBL8 收敛为 0，并在代码注释里标明这是字面取舍"）。
→ **让实现者交出"靠猜清单"，确实能把未来的分歧提前变成可复核的条目**；但**必须有环节去读它**。

**其余 14 个未定义边界，三个实现完全一致**（都选 Python 真值性、都把 bool 排除、
都不 clamp 负数、都精确匹配 type、都把垃圾输入计入总数、都把 `None` 当空输入）。
→ 结论：**"实现之间不一致"不是主要风险；"大家都朝同一个方向猜、且猜错了"才是**——
后者不会触发任何现有闸门（测试绿、形状绿、实现一致），只能靠人复核契约。

## 4. 实验台自身的教训（两条都是我（调度者）的错）

| 现象 | 根因 | 对设计文档的修正 |
|---|---|---|
| 两次"重生成"被污染：实现者读到的 `stats.py` 已经是别人填好的实现 | 我没有在重生成前把文件**复位成骨架** | **阶段 1 必须由评测器提供"冻结的骨架"**，不许让实现者自己去仓库里找输入 |
| 并发抢文件：子代理被要求"临时换入/换出 `stats.py`"，两个并发既互相污染又抢同一个备份名 | 我把"验证"这一步交给了实现者，还让它们写同一个路径 | **实现者不许写回原文件**；评测器用 `importlib` 加载候选文件自己跑证据；每个变体一个独立目录 |
| 子代理 r3 主动报告"我读到的不是骨架，这份产物不算独立实现"，拒绝过度声明 | 我在 prompt 里明确要求"必须写出没把握的地方、不许笼统" | **"要求如实报告"确实能显著提高诚实度**，但它只是 prompt 约定，不是闸门——规则仍须机器可查 |

## 5. 对设计文档的修正（实测推翻/证实的假设）

| 原假设 | 实测 | 修正 |
|---|---|---|
| §5.1 "契约改后重生成正确率"是最重要指标 | 三个实现**一次全绿**，该指标在这一步上**饱和**（区分不出好坏） | 换成更硬的指标：**契约缺口数**（实现者标出的歧义条数）+ **分歧探测数**（同契约不同实现的行为差异数） |
| §6 风险 1「契约不完备 → AI 补假设 → 语义漂移」 | 成立，但形态不同：漂移**不表现为实现分歧**，而表现为"一致地猜错"+ 文案级漂移 | 风险描述改为"**缺口不会被任何现有闸门发现**"，并要求把"靠猜清单"作为交付物 |
| §2 M3「证据挂在义务上」 | 证实：9 条证据在 3 个完全不同的实现上都直接复用、一条未改 | 保留；并加一条：**证据必须断言"输出本身"**，不能只断言"存在性/包含性"（实验 B 的 16 处漂移就是这么漏掉的） |
| §2 M2「骨架生成」 | 证实必要性，并暴露出实现细节：骨架必须是**冻结文件**，且数据段属于契约 | 补：骨架生成器要让"人决定的数据"原样落地，并给出**形状闸门**（`gate.py` 已可复用） |
| §3 R6/R7（不许改测试/契约） | 三个实现**零违例**（形状闸门 + 哈希 双重验证） | R6/R7 的实现优先度可以下调（但仍必须做：这次没违例，是因为 prompt 里明确禁止了） |

**有效性与局限（必须一起看）**

- **"人写契约的手感"这一项无有效证据**：两份契约都是我（AI）起草的。所有关于
  "人愿不愿意这样写 / 写契约是不是比写代码慢"的结论都**不成立**，需要你自己跑一遍。
- r2/r3 **存在记忆污染**：它们上一轮读到过 r1 的实现，自己主动声明了这一点。
  所以"三个独立实现"应理解为"三次独立作答 + 其中两次带前作先验"。
  要完全干净的样本，须在**新的上下文**里重跑（环境与脚本已就绪，重跑几分钟即可）。
- 样本量小：2 个模块、4 次实现、1 个模型族群。**不能外推到"所有模块/所有模型"**。
- 探测点是我设计的，只覆盖我想到的边界；真实系统里的边界更多。

## 7. 下一步（仍然先别写代码）

1. **补两行契约再各跑一次**（最便宜、信息量最大）：
   把 `auto`/`quiet` 的类型、`usage` 的形态、"输出格式"写进契约，看 16 处文案漂移与 2 处分歧是否**同时归零**。
   → 这直接验证"契约写清楚 = 行为收敛"。
2. **你自己手写一份契约**（哪怕只是把 `stats` 的契约改写一遍）：只有这一步能回答"手感"。
3. **定 D1–D5**（设计文档 §8），特别是 D5（是否接受"边也是一等公民"）。
4. 若 1 和 2 都好，再考虑阶段 1（反向提取契约）——**解析器是最后才写的东西**。
