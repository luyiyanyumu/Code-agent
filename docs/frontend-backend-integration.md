# 前后端联调

打开项目后，点击顶部“联调”，或选择“运行 → 前后端联调”。底部工具窗口包含“页面预览”“接口调试”“日志”和“配置”。

## 配置与启动

1. 在“配置”中为前端、后端分别选择启动方式。可以使用检测到的 npm、Maven、Gradle、Python 或 Node.js 运行配置，也可以填写自定义命令。工作目录和文件路径相对当前项目根目录。
2. 填写前端地址、后端地址。服务地址使用本机 HTTP 地址，例如 `http://127.0.0.1:5173/` 和 `http://127.0.0.1:8080/`。需要检查指定健康接口时，填写“后端健康检查地址”；该接口返回成功状态后才启动前端。
3. 需要固定端口或传入环境变量时，展开对应服务的高级选项。启动参数填写 JSON 字符串数组，环境变量填写 JSON 字符串键值对象。
4. 保存配置后点击“启动联调”。系统先启动并等待后端，再启动并等待前端；启动失败会显示原因，并清理本次创建的服务。

两个服务也可以分别选择“连接已有服务”。连接不会接管进程，停止时只断开联调。端口已被占用时，启动模式会报错；切换为连接模式可使用原有服务。

整体重启使用最新保存的配置。日志页还提供前端、后端各自的重启与停止操作，单端重启保留另一端。关闭工具窗口只暂停状态和日志观察；退出应用时会清理由本应用启动的进程。

## 页面和接口

服务就绪后，在“页面预览”点击“刷新预览”。预览使用真实开发服务返回的页面，页面发出的接口请求进入当前项目的联调代理，支持请求体、显式认证头和独立的 Cookie 登录会话。

“前端接口前缀”默认为 `/api`。例如后端地址为 `http://127.0.0.1:8080/`，页面请求 `/api/users` 默认转发为 `http://127.0.0.1:8080/api/users`；勾选移除前缀后，转发为 `http://127.0.0.1:8080/users`。直接请求所配置后端完整地址时，按后端基址转发，不重复处理前端前缀。

在“接口调试”中填写相对后端地址的路径，例如 `/api/users`，选择方法，按需填写 JSON 请求头和请求体，再发送请求。可以查看 HTTP 状态、耗时、响应头、响应内容，以及页面和手动请求的历史详情。历史记录会隐藏认证与密码等敏感字段；当前手动请求的即时响应保留原始内容，方便复制登录令牌继续调试。请求失败保留输入，不会自动重发写请求。

页面预览采用独立临时存储，重新载入后浏览器存储会重置；代理的 Cookie 会话随当前联调会话隔离。停止或整体重启后，旧页面的接口通道失效，需要重新刷新预览。

## 日志与更新

“日志”汇总前后端增量输出，可以按服务筛选、跟随输出、清空显示，并点击识别到的文件位置跳转到编辑器。日志有容量限制，较早内容超出限制时会提示截断。

当前预览在前端修改后需要手动刷新；尚未提供 HMR WebSocket 转发及 JavaScript 断点调试。原有 Python、Java 调试入口继续在“调试”面板使用。原有“前端设计”仍负责选择元素和保存样式，联调功能通过独立通道提供可写接口请求。

配置保存在本机用户数据目录的 `integration/configurations.json`，不会向业务项目写入配置文件。运行日志和接口历史不参与模型调用，使用联调无需模型 API Key。
