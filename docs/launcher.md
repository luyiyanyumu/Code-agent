# 桌面应用与运行维护

Code-agent 安装后直接打开 IDE 工作台，在一个主窗口中使用项目、编辑器和 AI 助手。后台服务自动准备，运行状态、重启、日志和更新收进工作台底部“应用状态”及设置中的“关于与诊断”。推荐使用包含运行环境的 [完整 Windows 安装包](windows-installer.md)。

> 本次启动器修改尚未发布到 npm。请使用当前源码；公共 `@latest` 仍是已发布的旧版本。

## 打开

完整安装包默认安装到 `%LOCALAPPDATA%\Programs\Code-agent`，通过桌面或开始菜单中的 **Code-agent** 打开。启动过程完成后自动进入工作台，不需要手动启动前后端或再点击“打开工作台”。

源码开发模式下，完成 README 中的依赖安装后，双击项目根目录的 `Code-agent.exe`。原有 VBS 和 BAT 入口继续兼容。此单独构建的 exe 需要与源码目录一起使用；完整安装包包含前后端、Node.js、Python、Git 和固定 WebView2 运行时。系统使用 Windows 10 / 11 x64 和 .NET Framework 4.8。

从源码重新构建 exe：

```powershell
npm run build:launcher
```

构建脚本位于 `scripts/build-launcher-exe.ps1`，生成项目根目录的 `Code-agent.exe`。单独的 exe 构建不包含运行环境；完整安装包使用 `npm run build:installer`。

终端入口：

```bash
npm run launcher
# 或
node bin/code-agent-launcher.mjs
node bin/code-agent.mjs launcher
```

重复打开同一安装目录的 exe 会唤起现有窗口。退出先检查未保存文件，再停止本次应用启动或重启的服务；复用的已有服务会保留。后端仍有任务或审批时，可返回工作台，也可明确选择保留后台并关闭窗口。

| 地址 | 用途 |
| --- | --- |
| 桌面窗口内的本机随机端口 | exe 的私有控制服务，无需手动访问 |
| `http://127.0.0.1:19387` | 保留的浏览器兼容控制面板 |
| `http://127.0.0.1:5175` | 前端工作台 |
| `http://127.0.0.1:8765` | 后端接口 |
| `http://127.0.0.1:8765/healthz` | 后端健康检查 |

源码模式使用项目 `.venv` 和 Vite。完整安装版使用安装目录内的 Python、Node.js 与预构建前端，启动不运行 npm 或 pip；用户数据和日志位于 `%LOCALAPPDATA%\Code-agent\data`。npx 发行方式仍支持直接 `start`，由后端在 8765 同端口提供界面。

## IDE 布局与快捷键

顶部菜单集中提供文件、编辑、导航、视图、运行和帮助命令。编辑器、思维导图与前端设计共用模式切换区；左侧工具栏打开项目、统一搜索、Git、调试和 AI。运行、问题、终端、调试与输出在底部工具窗口中切换，可拖动边界或聚焦边界后用方向键调整高度。

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl+P` | 查找文件 |
| `Ctrl+Shift+F` | 搜索代码 |
| `Ctrl+Shift+P` | 搜索并执行菜单命令 |
| `Ctrl+S` | 保存当前文件 |
| `Ctrl+Shift+S` | 保存当前项目全部已修改文件 |
| `Ctrl+B` | 显示或隐藏项目侧栏 |
| `Ctrl+Shift+F12` | 进入或退出专注模式 |
| `F12` | 跳转定义，需语言服务支持 |
| `Ctrl+Shift+Space` | 查看参数提示，需语言服务支持 |

专注模式暂时隐藏辅助面板，退出后恢复之前的布局；普通面板显隐和底部窗口高度会记忆到本机。“视图 → 恢复默认布局”可重置这些设置。全部保存会逐个使用原有保存与冲突检查流程，遇到错误或外部修改时停止并提示，不覆盖冲突。

## 清晰度与加载

Windows 系统文件夹选择器在独立辅助进程创建窗口前启用按显示器 DPI 感知，减少高分屏下的位图拉伸模糊；桌面版与浏览器模式使用相同的选择和取消流程。界面标志使用 SVG，保持不同缩放比例下的边缘清晰。

选择窗口不再把其他前台应用当作模态父窗口，避免超时清理后主窗口被留在禁用状态。请求断开会回收对应选择器，后端退出时辅助进程也会自行退出。关闭应用时显示检查和服务收尾进度，脚本与服务请求都有实际超时保护；未保存内容和后台任务仍受原有检查保护。

空工作区不再提前下载和初始化 Monaco，第一次打开文件时才加载编辑器，之后复用已加载的模块和本地 worker。普通并发状态请求共享正在进行的进程检查，前后端首次启动可并行；停止、重启与退出所需的身份和任务空闲检查仍单独执行。

Windows 服务身份检查通过内置 Python 的标准库直接读取系统监听表、进程命令行和创建时间，避免每次退出重复启动 PowerShell、编译辅助类型和执行 WMI 查询。停止时持有同一进程句柄，复核两轮监听归属后才结束该进程；两次后端空闲检查仍保留。读取失败会保留服务，不会降级为仅按 PID 强停。

本机使用离线模型、隔离空工作区各测三次，原生进程退出中位数由 22.246 秒降到 3.048 秒；文件夹选择器仍打开时退出实测 3.065 秒。本地 HTTP 状态检查复用线程内的连接处理器，不再初始化未使用的 HTTPS 证书环境。上述为本机测量，等待保存确认或运行中任务的时间不计入这一空闲退出指标。

本地性能测量可用 `node web/measure-empty-workspace.mjs <生产dist目录> <报告目录> 3`，记录真实资源请求、绘制、可用时间和截图。该脚本使用隔离的空项目 API 数据、4 倍 CPU 节流、150% DPR 与三个全新浏览器上下文，结果属于本机实验室指标。

## 模型与提供方

“设置 → 模型与连接”按提供方管理连接，一个提供方可保存多个模型。展开后输入 API 密钥；服务地址、模型列表、容量和代理位于“自定义设置”。密钥输入初始为空，留空保留已保存的密钥；获取模型后需勾选并点击“添加所选”，不会直接覆盖已有模型列表。

代码助手输入框旁的模型按钮与 `/model` 命令共用当前会话的模型目录，按提供方分组并支持搜索和键盘选择。选择保存在当前会话，下一次请求使用新模型，运行中的请求保留已捕获的模型与容量。移除提供方后，原有会话保留其选择并提示不可用，不会静默改用其他模型。

全局默认用于跟随默认的会话及后台功能描述；已单独选择模型的会话不受影响。选择器提供“跟随全局默认”以恢复继承。模型没有公布推理等级时不显示推理强度选项。

## 服务管理

- 应用自动启动尚未运行的服务。“应用状态”中可以分别恢复或重启前后端；重启界面前先保护未保存内容，恢复后自动重新载入。
- 服务区显示实际健康状态、进程和失败原因；主工作台始终复用主窗口。
- 后端停止或重启前会检查任务、待答问题和审批。有未完成工作时保留服务，并显示原因；无法确认空闲时同样不会强停。
- 端口被其他项目占用时显示归属异常，启动器不会停止该进程。
- 正常退出和 `stop-code-agent.bat` 使用进程归属与任务保护，不强停其他项目或无法确认归属的进程。

## 日志

“应用状态”的日志区可切换后端、前端、应用和更新，查看最近 200 行或打开完整日志目录。源码模式日志位于项目 `logs/`；安装包模式位于数据目录的 `logs/`。操作失败的提示会保留，日志内容会隐藏常见密钥和凭据。

## 更新

“检查更新”显示真实检查结果；失败时显示原因，服务继续运行。

**源码模式：** 检查配置的官方 GitHub 跟踪分支。执行更新前需先停止前后端；存在未提交或未跟踪的文件时会直接拒绝更新，保留全部本地改动。干净分支仅允许快进，不自动合并分叉，不执行重置、清理或暂存。更新后安装依赖、构建前端与内核并检查后端导入，完成后再启动服务。若源码已更新但构建失败，日志会说明阶段，需要先修复并重新构建。

**完整 Windows 安装版：** 检查官方 GitHub Releases 的安装包版本，按提示下载并运行新版安装包。升级前退出应用；若安装器发现该目录仍有后台服务，可点击“停止后台并重试”，仅在任务空闲且确认进程归属后继续。用户数据保持独立。当前本地安装包尚未公开发布，界面会显示实际检查结果。

**npx 模式：** 从官方 npm 包下载并准备最新版运行环境，保留当前服务、会话、配置和密钥。待新版发布后，停止旧服务并通过新版入口启动：

```bash
npx @luyiyanyumu/code-agent@latest launcher
```

继续使用原来的 `--home` 数据目录。这里的命令需等包含启动器的新版包发布后使用，当前公共 npm 旧版不支持 `launcher`。

## 参数与旧脚本

```bash
# 显式使用兼容网页面板，自定义面板端口与数据目录
node bin/code-agent-launcher.mjs --web --launcher-port 19388 --home "D:/Code-agent-data"

# 仅运行兼容控制服务，不打开窗口
node bin/code-agent-launcher.mjs --no-open
```

`start-code-agent.vbs` **不带参数**时打开新面板；显式传入 `--start-only`、`--no-open` 或 `--restart-backend` 时，继续执行原服务启动流程，便于已有自动化复用。例如：

```powershell
cscript //nologo start-code-agent.vbs --start-only --no-open
```

`--no-open` 在兼容控制服务入口表示“不自动打开面板”；在旧 VBS 服务入口表示“不打开工作台”。桌面 exe 不依赖已经打开的 `19387` 浏览器标签页。

## 本地验证

真实 FastAPI 后端与 Vite 前端使用隔离数据目录和端口，已完成一键启动、各自重启、全部停止、停止后恢复和再次停止，日志读取与代理接口通过。该过程不调用模型，也不修改用户原有会话。

复现命令：`node scripts/verify_launcher.mjs`。相关 npm 测试覆盖进程管理、更新保护、HTTP 接口与安装包预览；Windows 测试覆盖进程归属、旧脚本兼容、任务空闲保护和启动健康检查。

桌面验收脚本 `scripts/verify_desktop_ide.mjs` 使用真实安装目录、隔离的数据与端口，检查主窗口直接进入工作台、原生状态与日志桥接、后端重启及正常退出时停止自身服务。桌面桥接、窗口打开及退出恢复的回归位于 `npm/tests/desktop-launcher.test.mjs`。界面脚本 `web/verify-ide-layout.mjs` 在隔离 API 数据下检查菜单、真实编辑器保存流程、面板布局、命令面板和窄屏交互。

退出性能可用 `node scripts/verify_desktop_shutdown.mjs <安装目录> <报告目录> 3` 复测。每轮使用隔离数据和离线模型，记录原生进程退出事件并核对本次服务与控制器均已退出；事后端口和进程核验耗时单独记录。
