# 编码助手记忆

设置中的“记忆”管理三种范围：

| 范围 | 使用者 | 建议内容 |
| --- | --- | --- |
| 个人 | 同一用户的所有项目与会话 | 输出偏好、长期工作习惯 |
| 项目 | 同一项目的 Lead、节点、子智能体和任务工作树 | 项目背景、编码约定、已经确认的决策 |
| 会话 | 保存它的会话 | 当前任务的特定背景 |

项目记忆存放在平台数据目录 `code/<project_id>/memory`，会话记忆存放在平台的 `workspaces/<session_id>/memory`，不向代码仓库写入平台记忆。独立 CLI 可以显式使用自己的工作区。

`save_memory` 支持 `user/project/session/workspace`。`workspace` 为兼容别名，项目会话保存到项目共享记忆，普通会话保存到会话记忆。内容最多 1,000 字符，支持多行和分类，记录实际保存它的会话来源。它适合稳定事实，不适合暂时的错误、权限拒绝或未经验证的推断。

每条记录有稳定 ID、来源、分类、创建和更新时间以及启用/置顶状态。页面提供搜索、范围和状态筛选、编辑、停用、置顶和确认删除。停用保留内容，但后续任务准备上下文时不再检索它。置顶优先参与上下文，仍受条数和字符预算限制。

实际检索合并当前项目、当前会话和个人的已启用条目，规范化重复内容，优先采用更接近当前会话的来源。非置顶内容按关键词相关度检索，支持中文二元组和 CamelCase/snake_case 标识符拆分。默认最多 5 条、完整数据块不超过 4,000 字符；每条标注来源。记忆作为参考数据注入，不能扩大工具权限或替代当前用户指令。

旧 `MEMORY.md` 在首次访问时导入元数据，保留原文。`memory-records.json` 保存记录和版本，Markdown 保持可读、可编辑。外部修改会被重新核对；界面更新带版本校验，冲突时保留草稿并要求核对最新版本。写入采用跨线程、跨进程锁及可恢复镜像事务，避免中断后丢失稳定 ID 或重新启用停用条目。

日常任务日志、工具失败和临时权限拒绝进入每日日志，不自动变为长期记忆。原有长期条目继续保留，可由用户在页面中核对和管理。
