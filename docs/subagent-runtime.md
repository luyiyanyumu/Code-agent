# 子智能体协作

本地编排用于 DeepSeek 和其他 Chat Completions 兼容模型。项目 Lead 可以亲自执行，也可把有独立交付物、有并行收益的工作委派给后代，再核对结果并交付。简单连续步骤由当前执行者完成；已有适合的执行者优先继续使用。所有深度的后代共享项目并发上限，Lead 不占名额。

## 委派与继续

- `delegate_agent` 按需创建子任务；必填 `prompt`、`write_paths` 和 `delegation_reason`。理由需说明独立交付物与并行收益；创建智能体不是默认步骤。
- `send_agent_message` 将补充消息持久化到目标收件箱，不启动空闲智能体。繁忙智能体在下一次模型调用前接收消息。
- `followup_agent` 复用空闲智能体的会话和工作区，创建新的 `activation_id`，必填 `delegation_reason` 说明复用价值。省略 `write_paths` 时继承上一轮范围；显式 `[]` 改为只读。繁忙目标应先接收消息或中断当前轮次。
- `interrupt_agent` 中断目标当前轮次，保留后代任务与历史；`stop_agent` 停止目标及整棵后代树。
- `wait_agents` 的 `all` 模式保留全部完成屏障；`any` 模式可在任一任务结束或出现真实待审批申请时返回。将返回的 `cursors` 作为下一次 `after_cursors`，避免重复读取旧结果。

## 写入范围与依赖

`write_paths` 是工作区相对路径数组，最多 64 项，每项最多 1024 字符。`[]` 表示只读；`["src/api.py"]` 只允许该精确文件；`["src/api/"]` 声明目录及后代；`["."]` 声明整个工作区独占。已有目录会自动归一为带末尾 `/` 的目录范围；其他文件名不按路径前缀扩权。调度器按声明范围排队，同一文件在执行阶段只有一个写者；已持有整个工作区范围的任务会阻挡该工作区的其他写任务。子任务的范围仍受祖先授权、权限及工作树边界约束，声明范围不能提升权限。

任务等待子任务或审批、且没有实际工具执行时，会交还执行名额及执行阶段的文件持有权。恢复前重新排队，重新取得两者，并复核工作区、有效权限与当前范围。范围冲突时继续等待；校验失败时本次执行失败，不能把它当成普通工具错误继续调用模型或写文件。任务结束、中断或取消也会清理持有权。`write_paths` 是任务级范围声明，工具执行时的短写租约仍保证实际同路径写入互斥。

`depends_on` 可指定最多 16 个已存在且有权访问的后代会话 ID。服务端绑定这些会话**当前的 `activation_id`**，不跟随未来的继续派工：绑定执行全部成功后本任务才进入执行；任一依赖失败或取消，本任务失败。继续派工的新轮默认没有依赖，不继承上一轮绑定的旧执行；显式 `[]` 也表示没有依赖，需要前置任务时重新传入 ID 绑定当前执行。不会因为有依赖而提前占用执行名额。

例如将互不重叠的实现与文档任务分别声明为 `write_paths: ["src/service.py"]` 和 `write_paths: ["docs/"]`；后续集成任务声明 `write_paths: ["."]`，并通过 `depends_on` 指向这两次执行。派工及状态回执保留 `write_paths`、`scope_mode`、`delegation_reason`、`file_ownership` 和绑定后的 `depends_on`。大型回执将完整 JSON 存在 `full_roster_path`，通过明确路径读取，不把被省略的范围当成额外授权。

公开模型工具必须显式声明新任务范围和派工理由；缺项或类型不合法会在创建会话前拒绝。为兼容内部旧 Python 调用，未声明范围的新执行按保守策略处理：只读权限对应空范围，否则按全工作区独占。旧历史记录显示为旧版本未声明范围，不伪造历史授权。人工 HTTP 继续接口的理由与范围保持可选；未传范围时继承上一轮。

## 可执行工具边界

只读或精确文件/目录范围的子任务，不能用任意 shell 或无法判断写入目标的插件操作来绕过范围检查。集成测试、构建及其他可能写缓存或生成文件的命令，交由 Lead 执行，或在独立工作树内委派 `write_paths: ["."]` 的任务。先完成范围内原生文件修改，再由有相应范围与权限的执行者验证。

同一执行者的写入、Shell 和未知副作用工具在最终分发处串行；不同执行者仍可并行修改各自独占的文件。排队后重新核对执行身份、工作区和有效权限，权限变化时旧调用须重新尝试或申请。`run_in_background` 等脱离当前调用的后台写入模式会被拒绝，避免工具提前返回、文件责任已经释放而后台仍在写入。

工作树减少分支与文件冲突，**不是安全沙箱**；声明全范围不会阻止 shell 访问操作系统其他位置，仍需遵守原有权限、审批与工作区策略。

## 上下文

`context_strategy` 默认 `task_brief`，包含父任务目标、最近用户约束、标明尚需核验的智能体报告和工具证据摘录；`none` 不继承父历史；`all` 继承已配对的完整对话快照。审批和生命周期事件不继承。工作区与权限单独控制。

长会话保留带原始轨迹 `seq` 的工作检查点，记录目标、约束、声明的决定、实际工具返回和待办。检查点采用确定性摘录，不调用额外模型，也不把工具返回视为验收通过。完整 JSONL 轨迹保留。

## 审批和进度

配置权限不被祖先临时收紧后的有效权限覆盖。审批只授权一次具体操作。等待审批期间，仅在没有实际工具执行时释放并发名额；授权后重新排队、检查工作区与权限，再执行。

工具结果完成即显示，模型仍收到全部、按调用顺序排列的结果。同批次写入与 shell 是顺序屏障；独立会话写不同路径仍可并行。同路径写入统一经过共享短租约，取锁后重新检查权限；取消等锁者只退自身引用，不会释放实际持有者的锁。任意 shell 修改仍需任务工作树隔离和协调，不能从命令文本可靠推断所有写入路径。

执行与继续派工会检查完整祖先链；关闭、归档或退役的中间祖先不能被深层后代绕过。等待子任务或审批后恢复执行时，统一重新申请名额，并复核深度、工作区和权限；恢复失败直接终止该次执行，不作为可继续运行的普通工具错误。

团队阶段与回执通过现有会话 WebSocket 通知；断线有轮询兜底。收件箱投递由服务端编号确认，重启和对话回退会核对保留的投递事件，不会因为引用文本中的标记而误确认消息。

回执在模型边界按最多 40,000 字符的批次投递，只确认已加入模型历史的本批消息，其余保留。自动唤醒沿用次数与预算限制；非主动停止、非账户阻断的异常收尾也会检查晚到回执。超长旧通知保留全文存盘，并投递带路径的明确摘录。

## 可选预算

设置中的 `task_tokens/task_seconds/team_tokens/team_seconds` 默认均为 `0`（关闭）。任务预算绑定一次执行；团队预算覆盖一次 Lead 用户任务及其递归后代，完成通知唤醒沿用团队预算。新的用户任务创建新预算范围。

委派及继续工具可传 `budget: {"max_tokens": 100000, "max_seconds": 600}`。配置的任务预算是上限，单次委派不能放宽它。Token 包含输入和输出，缓存 Token 已包含在输入中。达到限额后停止请求下一轮模型；已在途的请求可能超过限额。耗时包含排队、审批与等待子任务。已消耗的团队 Token 不因删除子会话而退回。

本次实现没有接入 OpenAI Responses 托管多智能体。该模式需要独立的传输、事件和编排适配器。
